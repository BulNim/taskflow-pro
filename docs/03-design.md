# 03-design.md

| # | 선택 | 대안 | 근거 | 트레이드오프 |
|---|---|---|---|---|
| 1 | 백엔드 - FastAPI | Django, Express | 가볍고 비동기 지원이 기본이며, 타입 힌트 기반 자동 검증/문서화로 소규모 팀 유지보수에 유리 | Django 대비 관리자 페이지, ORM 등 배터리 포함 기능이 없어 필요 시 직접 구성해야 함 |
| 2 | 프론트 - Vanilla JS + Tailwind CDN. API 호출은 상대경로 `fetch(/api/...)` 고정, 절대경로 금지 | React, Vue | 빌드 도구 없이 파일 2개(`index.html`, `app.js`)만으로 구동 가능해 MVP 단계에서 설정 비용이 없음 | 컴포넌트 재사용, 상태관리 도구 부재로 화면/상태가 늘어나면 코드가 장황해질 수 있음 |
| 3 | DB - SQLite (SQLAlchemy ORM, 추후 PostgreSQL 전환 고려) | PostgreSQL 즉시 도입 | 로컬 파일 기반이라 별도 서버 설치 없이 즉시 개발 가능, ORM을 통해 추후 전환 시 코드 변경 최소화 | 동시 쓰기 처리량이 낮아 다중 사용자 트래픽 증가 시 PostgreSQL 전환이 필요함 |
| 4 | CSS - Tailwind만. styled-components 금지 | - | 유틸리티 클래스만으로 Mac OS 톤(둥근 모서리, 그림자, 블러)을 빠르게 구현 가능, CDN 방식이라 빌드 단계 불필요 | CSS-in-JS 대비 클래스명이 길어지고 컴포넌트 단위 스타일 캡슐화는 약함 |
| 5 | 실시간 - MVP는 폴링 3초, WebSocket은 확장 단계 보류 | - | 폴링은 구현이 단순하고 FastAPI 기본 REST 구조만으로 충분, 10명 규모 팀 트래픽에서는 성능 이슈 없음 | 실시간성이 떨어지고(최대 3초 지연), 사용자/서버 증가 시 불필요한 요청 부하 발생 |
| 6 | 상태관리 - 모듈 변수 + DOM 직접 갱신 | - | Vanilla JS 구조와 맞물려 추가 라이브러리 없이 상태를 추적 가능, MVP 규모의 화면 수에서는 복잡도가 낮음 | 화면/상태가 늘어나면 변수와 DOM 갱신 로직이 흩어져 추적이 어려워질 수 있음 |
| 7 | 디자인 시스템 - Mac OS UI 톤. 토큰: `rounded-xl`, `shadow-lg`, `backdrop-blur`, 시스템 폰트 | Material, Ant | 팀리더 페르소나가 익숙한 macOS 감성의 부드럽고 신뢰감 있는 UI를 별도 컴포넌트 라이브러리 없이 Tailwind 토큰만으로 구현 가능 | 디자인 시스템 라이브러리(Material, Ant) 대비 사전 정의된 컴포넌트가 없어 일관성 유지를 직접 관리해야 함 |
| 8 | 테마 - 라이트/다크 토글, `localStorage('theme')`, 초기값 `prefers-color-scheme` | - | 사용자가 선택한 테마를 새로고침 후에도 유지하면서, 최초 방문 시에는 시스템 설정을 존중 | localStorage 값과 시스템 설정이 달라지는 경우(설정 변경 등) 동기화 로직을 별도로 관리해야 함 |
