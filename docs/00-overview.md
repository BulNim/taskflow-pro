`00` > `01` > `02` > `03` > `04` > `05`

## 왜 이렇게 나누는가 - 관심사 분리

한 문서에 목적·명세·설계·일정·규칙을 모두 적으면 무엇 하나를 고칠 때마다
문서 전체를 다시 읽어야 하고, 어디까지가 확정이고 어디부터가 의견인지 흐려진다.

- **왜(01)** 와 **무엇(02)** 을 나누면 요구가 바뀌어도 API 명세가 흔들리지 않는다.
- **무엇(02)** 과 **어떻게(03)** 를 나누면 기술을 바꿔도 명세는 그대로 남는다.
- **순서(04)** 를 따로 두면 진행 상황이 설계 문서를 오염시키지 않는다.
- **규칙(05)** 을 따로 두면 모든 구현 단계가 같은 기준을 참조한다.

각 문서는 자기 관심사만 책임진다. 그래서 고칠 곳이 항상 한 곳으로 정해진다.
